HubPilot 1.0.1 - release validation
===================================
Date: 2026-08-24

Release changes
---------------
1.0.1 includes two post-release improvements:

1. Per-server Always-On server lifecycle option.
2. Live Navigator telemetry refresh while the GUI stays open.

Always-On server is separate from the Always-On provider. A server can still use Crafty, Pterodactyl, Generic HTTP, or another managed provider while being marked Always-On.

When Always-On server is enabled, HubPilot keeps provider startup and manual Stop Server available but disables automatic shutdown for:
- idle time
- failed player requests
- an empty startup/request queue

Open Navigator menus now re-render their server entries after a complete status sync. Players do not need to close and reopen the Navigator to see updated status, player counts, ping, startup progress, queue information, uptime, or any other telemetry already rendered by the server item.

Live field acceptance
---------------------
Always-On server has live Velocity + Paper/Crafty acceptance coverage for the two most important runtime boundaries:
- a managed backend remained online past a deliberately shortened idle-shutdown window while Always-On server was enabled.
- manual/debug Stop Server still stopped that same Always-On server as intended.

The new live Navigator refresh has exact packaged-code harness coverage but still needs its final visual field check on the live Paper hub before 1.0.1 should be promoted from pre-release to stable.

Compatibility note
------------------
Core and Hub should be updated together to 1.0.1.

Interact 1.0.0 and Link 1.0.0 remain compatible with 1.0.1 because neither component has functional changes in this release. Matching 1.0.1 JARs are still provided to keep the suite on one public version number.
