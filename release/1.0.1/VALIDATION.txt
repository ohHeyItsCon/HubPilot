HubPilot 1.0.1 - release validation
===================================
Last updated: 2026-08-26

Release changes
---------------
1. Per-server Always-On server lifecycle option.
2. Live Navigator telemetry refresh while the Navigator GUI remains open.
3. Crafty-backed discovery and dynamic Velocity registration.
4. Duplicate discovery migration and Navigator cleanup.
5. Shared Admin and player Navigator layout.

Always-On server
----------------
This is separate from the Always-On provider. A Crafty, Pterodactyl, Generic HTTP, or other provider-controlled server can be marked Always-On while keeping provider startup and manual Stop Server available.

When enabled, HubPilot disables these automatic shutdown paths for that server:
- idle shutdown
- failed-request shutdown
- queue-empty shutdown

Live Navigator refresh
----------------------
The Hub now refreshes an already-open server Navigator when a complete STATUS_SYNC_END packet is received. The current top inventory is rebuilt from the latest StatusStore/telemetry data, its contents are replaced in place, and Player.updateInventory() is called. The GUI is not closed or reopened.

Field-test correction
---------------------
The first 1.0.1 pre-release Hub JAR advertised live Navigator refresh, but that packaged JAR did not actually contain the refresh class or the STATUS_SYNC_END hook. A real network test caught the problem because telemetry only changed after reopening the Navigator.

The corrected 1.0.1 Hub JAR was rebuilt and revalidated. Exact packaged-bytecode inspection confirms:
- dev/hubpilot/hub/gui/NavigatorLiveRefresh.class is present.
- HubPilotFeedbackListener.readStatus calls NavigatorLiveRefresh.refreshOpen(...) on STATUS_SYNC_END.
- the refresh path updates only open DestinationMenuHolder inventories.
- unrelated open inventories are ignored.
